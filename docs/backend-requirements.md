# leaf & bowl 백엔드 요구사항

고객의 주문을 서버에 접수하고 관리자가 주문을 확인·처리할 수 있도록 백엔드를 구성한다. 상품·옵션·재료·리뷰와 주문 데이터를 영속 저장하고 고객·관리자 화면에 일관되게 제공한다. 아래는 구현을 위한 검토 초안이다.

## 범위

주문 생성·조회·상태 변경·취소, 관리자 인증, 상품·옵션·재료·리뷰·콘텐츠 관리, 이미지 업로드와 데이터 이관을 포함한다. 프론트엔드의 체험 주문을 서버 주문 접수로 연결한다. 매장 정보 관리 기능은 제외한다. PG 결제·환불, 고객 계정 및 판매 집계는 별도 범위로 결정한다.

## 기능 요구사항과 수용 기준

| ID | 요구사항 | 완료 조건 |
| --- | --- | --- |
| BE-01 | 관리자 인증·권한 | 로그인·로그아웃·세션 만료를 지원한다. 비로그인 사용자의 관리자 조회·수정·업로드 API 접근을 거부한다 |
| BE-02 | 상품·옵션·재료 관리 및 조회 | 가격·분류·알레르기·선택 규칙·연결·순서·판매 상태를 저장한다. 공개 목록에서 숨김·삭제 항목을 제외하고 품절을 표시한다. 상품 API와 카탈로그 값이 일치한다 |
| BE-03 | 주문 생성 | 상품·옵션·재료·수량, 주문자·연락처·배달 주소·희망 시간을 검증한다. 서버가 최신 가격·배달비·최소 금액·배달 가능 조건을 계산하고 주문 번호와 접수 결과를 반환한다 |
| BE-04 | 주문 중복 방지 및 기록 | 같은 주문 요청을 재전송해도 주문은 한 건만 생성한다. 주문 당시 상품명·선택 구성·단가·수량·총액을 보존하고 이후 상품 변경으로 주문 내역을 바꾸지 않는다 |
| BE-05 | 주문 조회 | 고객은 본인 주문의 상세와 상태를 확인한다. 관리자는 기간·상태별 목록과 상세를 조회한다. 주문 번호만으로 타인의 주문·연락처·주소를 조회할 수 없다 |
| BE-06 | 관리자 주문 처리 | 접수·확인·준비 중·배달 중·완료 상태를 관리한다. 허용된 순서로만 변경하고 변경자·시각·이력을 기록한다. 같은 주문의 동시 변경은 덮어쓰지 않는다 |
| BE-07 | 주문 취소 | 준비 시작 전 고객 본인 또는 관리자가 취소할 수 있다. 취소 사유와 시각을 기록한다. 준비 중·배달 중·완료 주문의 일반 취소는 거부하고 이미 취소된 요청은 중복 처리하지 않는다 |
| BE-08 | 리뷰 작성·관리 | 작성·조회·삭제·복원을 지원하고 별점 1~5 및 입력을 검증한다. 생성 시각을 보존하며 같은 ID 재전송은 중복 생성·삭제 리뷰 복원을 발생시키지 않는다 |
| BE-09 | 콘텐츠 및 이미지 관리 | 홈·시즌 문구·노출·연결 상품을 저장한다. 관리자 업로드는 PNG·JPEG·WebP, 5MB 이하 및 파일 시그니처를 검증하고 이미지가 재배포 후에도 유지된다 |
| BE-10 | 동시 저장·기존 데이터 보존 | 오래된 revision은 409로 거부하고 부분 실패는 롤백한다. 상품 ID·customerId·재료·리뷰·이미지·기존 URL을 보존하며 동시 주문·상품 수정·리뷰 저장으로 데이터가 유실되지 않는다 |

## 시스템 요구사항

- 현재 leaf-bowl 레포와 Next.js 앱 하나에서 고객·관리자 화면 및 API를 함께 개발·배포한다. 동일 접속 도메인의 `/api/*`를 사용한다.
- 백엔드 API는 Next.js Route Handlers로 구현하고 Prisma로 PostgreSQL에 접근한다. DB 모델과 변경 이력은 Prisma schema·migration으로 관리한다.
- 운영·검증은 기존 배포 환경을 사용하고 DB·이미지 저장 영역을 구분한다. DB 접속 정보와 Prisma Client는 서버 코드에서만 사용한다.
- API 명세에 요청·응답·권한·오류를 정의한다. 인증 실패·권한 부족·검증 실패·충돌·장애를 구분한다.
- 비밀번호는 안전하게 해시하고 세션 쿠키 보호·변경 요청의 CSRF 방어·로그인·주문·리뷰 요청 제한을 적용한다. 주문 조회 권한을 검증하고 연락처·주소·인증정보를 공개 응답·로그에 노출하지 않는다.
- 기존 Frontend CI에 Prisma 검증 및 DB 통합 테스트를 추가해 앱 전체의 배포 게이트로 사용한다. 이관 전 백업, 이관 후 데이터 대조, DB·이미지 복원 및 배포 실패 복구를 확인한다.

## 검증과 미정 사항

완료 검증은 정상 주문 접수, 가격 변조·품절·잘못된 옵션 거부, 중복 주문 방지, 타인 주문 접근 차단, 주문 상태 전이·취소·동시 변경, 기존 데이터 보존 및 재시작·백업 복원으로 수행한다.

비회원 주문 인증 방식, 주문 상태·취소 기준, 주문·개인정보 보관 기간, 배달 조건 및 결제 연동 여부를 구현 전에 확정한다. 기존 [DB 설계](db-design.md)에 재료·주문·처리 이력을 추가한다. 구현 방식은 [백엔드 설계](backend-design.md)를 따른다.
